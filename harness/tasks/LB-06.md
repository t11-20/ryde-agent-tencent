# LB-06 — Fare check and remedy basis

**Goal:** validate fare arithmetic in integer cents and compute what each remedy is allowed to pay.
**Requires:** LB-05 · **Who:** agent · **SPEC:** §5.8, §5.9, §7 (fare table) · **Screenshot moment:** no

## Files

Create: `packages/evidence/src/fare.ts`, `packages/evidence/src/remedy.ts`, `packages/evidence/test/fare.test.ts`, `packages/evidence/test/remedy.test.ts`
Modify: `packages/evidence/src/index.ts`, `harness/STATUS.md`

## Steps

1. `fare.ts`:
```ts
import type { Fixture } from './schemas.js';
export type AvailablePayment = Extract<Fixture['payment'], { status: 'available' }>;
export interface FareCheck { arithmeticValid: boolean; anomalies: string[] }
export function checkFare(payment: AvailablePayment): FareCheck;   // SPEC §5.8, codes in the table's order
```
Guard every `divHalfUp` call: if `quantity` is missing or any input is not a non-negative safe integer, record the anomaly code for that check and skip the call.

2. `remedy.ts`:
```ts
import type { RemedyId } from '@fairtrip/contracts';   // if this type is not exported, use: 'keep_charge' | 'refund_route_excess' | 'refund_no_show_fee'
export interface RemedyBasisEntry { remedyId: 'keep_charge' | 'refund_route_excess' | 'refund_no_show_fee'; eligibleCents: number | null; formula: string; unavailableReason: string | null }
export function remedyBasis(fixture: Fixture, route: RouteMetrics | null, fare: FareCheck | null): RemedyBasisEntry[] | null;  // SPEC §5.9
```
Use the literal union for `remedyId` (do not import a `RemedyId` type unless `@fairtrip/contracts` exports one). Return `null` when `fixture.payment.status !== 'available'`. Reasons must be the exact strings in SPEC §5.9.

3. Export both from `src/index.ts`.

4. `test/fare.test.ts`:
- every fixture with an available payment gives `arithmeticValid: true` and `anomalies: []`;
- line items and totals match SPEC §7 (for example R1 `base 300, distance 795, time 378`, total `1473`; R1S surge `737`, promo `-300`, total `1910`);
- each mutation of a `structuredClone` of R1's (or R1S's, or N1's) payment adds the expected code (assert with `toContain`):
  currency `'USD'` → `currency_not_sgd`; base cents `301` → `base_mismatch`; distance cents `+1` → `distance_mismatch`; time cents `+1` → `time_mismatch`; R1S surge cents `+1` → `surge_mismatch`; R1S promo cents `+300` → `promo_positive`; R1 time cents `-378` → `negative_item`; N1 fee cents `400` → `no_show_fee_mismatch`; `totalCents + 1` → `total_mismatch`; `paidCents - 1` → `paid_mismatch`; distance cents `795.5` → `non_integer_amount`.

5. `test/remedy.test.ts` (compute `route` with `routeMetrics` and `fare` with `checkFare`):
- R1 `refund_route_excess` 198; R1S 297; R2 116; R3 129; their `refund_no_show_fee` is `null` with reason `not applicable to category`;
- N1, N2, N2H, N3, X2 `refund_no_show_fee` 500;
- X1 `refund_route_excess` is `null` with reason `GPS route metrics unavailable`;
- X3 → `remedyBasis(...)` returns `null`;
- `keep_charge` is always `{ eligibleCents: 0, unavailableReason: null }`;
- R1 with `{ ...route, exceedsThreshold: false }` → `refund_route_excess` null, reason `detour not material under RD-1`;
- R1 with an invalid fare (`{ arithmeticValid: false, anomalies: ['total_mismatch'] }`) → both refunds null, reason `fare arithmetic invalid` for the route refund.
