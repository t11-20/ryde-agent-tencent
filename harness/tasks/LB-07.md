# LB-07 — Evidence builder and policy clauses

**Goal:** turn each fixture into Lane A `Evidence` records with readable summaries, plus policy clauses per category.
**Requires:** LB-06 · **Who:** agent · **SPEC:** §6 (all), §7 · **Screenshot moment:** no

## Files

Create: `packages/evidence/src/facts.ts`, `packages/evidence/src/build-evidence.ts`, `packages/evidence/src/policy.ts`, `packages/evidence/test/build-evidence.test.ts`
Modify: `packages/evidence/src/index.ts`, `harness/STATUS.md`

## Steps

1. `facts.ts`: copy the `asFacts` helper from SPEC §6.2.
2. `policy.ts`:
```ts
import type { PolicyClause } from '@fairtrip/contracts';
import type { PolicyDoc } from './schemas.js';
export function policyClausesFor(policy: PolicyDoc, category: PolicyClause['category']): PolicyClause[];  // filter, keep file order, return copies
```
3. `build-evidence.ts`:
```ts
import type { Evidence } from '@fairtrip/contracts';
export interface UnavailableFamily { family: Evidence['source']; reason: string }
export interface EvidenceBundle { records: Evidence[]; unavailable: UnavailableFamily[] }
export function buildEvidence(fixture: Fixture, policy: PolicyDoc): EvidenceBundle;
```
Build in the order of SPEC §6.1 using `routeMetrics`, `pickupMetrics`, `analyseChat`, `checkFare`, `remedyBasis`. Write one small function per record kind (`gpsRouteRecord`, `navRecords`, `advisoryRecords`, `pickupRecord`, `chatRecords`, `paymentRecords`, `historyRecords`) so each stays short. Every record:
```ts
{ id, source, timestamp, facts: asFacts({ kind, summary, ...fields }), provenance: { kind: 'fixture', description: `Synthetic fixture ${fixture.fixtureId}: ${method}` } }
```
Use the timestamps and methods from SPEC §6.2 and the facts fields and summary templates from SPEC §6.3. For PAY-FARE, write line items as `{ code, label, cents, quantity: item.quantity ?? null }`.
4. Export the three modules from `src/index.ts`.
5. `test/build-evidence.test.ts` (import `EvidenceSchema`, `PolicyClauseSchema` from `@fairtrip/contracts`):
- for every fixture: each record passes `EvidenceSchema.parse`; `records.map(r => r.id)` equals SPEC §6.4 exactly; `unavailable` families equal SPEC §6.4 and each `reason` equals the fixture's `reason` text;
- every record has `facts.kind` (string) and a non-empty `facts.summary`;
- building the same fixture twice gives deep-equal output;
- summary phrases: R1 GPS-ROUTE contains `EXCEEDED (material detour)` and `+2642 m`; N1 GPS-PICKUP contains `NOT MET` and `never within 150 m`; N3 GPS-PICKUP contains `Waited 210 s` and `NOT MET`; N2 CHAT-SUMMARY contains `Driver contact attempts before cancellation: 3`; R1 PAY-FARE contains `S$14.73` and `VALID`; R1 PAY-REMEDY contains `refund_route_excess S$1.98`;
- X2 CHAT-04: `facts.tags` contains `instruction_like` and `facts.text` equals the exact message from LB-05;
- fairness (N2 vs N2H) and injection (N2 vs X2): GPS-PICKUP `closestApproachMeters`, `waitSecondsWithinThreshold` and `checks` are equal; CHAT-SUMMARY `driverContactAttemptsBeforeCancel` is equal; PAY-REMEDY `basis` is equal; for N2H, HIST-DRIVER facts differ from N2's;
- `policyClausesFor(policy, 'route_deviation')` IDs are RD-1…RD-7, `'no_show'` gives NS-1…NS-4, and every clause passes `PolicyClauseSchema.parse`;
- R1 PAY-FARE `facts.lineItems[0].quantity` is `null` (never `undefined`).

To read a fact in a test, narrow it: `const facts = record.facts as Record<string, unknown>;`.
