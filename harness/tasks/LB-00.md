# LB-00 — Setup and baseline

**Goal:** start a clean Lane B branch from `main`, add this harness, and prove Lane A passes before anything changes.
**Requires:** nothing · **Who:** human (H1–H5), then agent (A1–A4) · **SPEC:** none · **Screenshot moment:** YES

## Human steps (do these yourself, outside the agent)

H1. Install **Node 22.23.3** and **npm 10.9.9** exactly. The repo refuses other versions.
- macOS / Linux (nvm): `nvm install 22.23.3 && nvm use 22.23.3 && npm install -g npm@10.9.9`
- Windows (nvm-windows, from an administrator terminal): `nvm install 22.23.3`, `nvm use 22.23.3`, then `npm install -g npm@10.9.9`
- Check: `node -v` prints `v22.23.3`; `npm -v` prints `10.9.9`.

H2. Get a clean copy and create the branch:
```
git clone https://github.com/t11-20/ryde-agent-tencent.git
cd ryde-agent-tencent
git switch -c lane-b-codebuddy origin/main
```
(If you already have a clone: `git fetch origin`, make sure `git status` is clean, then `git switch -c lane-b-codebuddy origin/main`.)

H3. Unzip the harness into the repository root so these exist: `CODEBUDDY.md`, `AGENTS.md`, `.codebuddy/rules/`, `.codebuddy/commands/`, `harness/`.

H4. In CodeBuddy: **Open Folder** → the repository root. Choose the agent model. Open a **new chat**.

H5. Type `/lb-task LB-00`. If slash commands do not appear, paste prompt P1 from `harness/PROMPTS.md` with `LB-00`.

## Files (agent)

Modify: `harness/STATUS.md`. Commit the new harness files. Nothing else.

## Agent steps

A1. Run `node -v` and `npm -v`. They must print `v22.23.3` and `10.9.9`. Otherwise STOP and tell the human to repeat H1.

A2. Run `git branch --show-current` (must print `lane-b-codebuddy`) and `git status --short`. Only untracked harness paths may appear (`CODEBUDDY.md`, `AGENTS.md`, `.codebuddy/`, `harness/`). Anything else: STOP.

A3. Run `npm ci`, then `npm run verify`. Expected output includes:
- `Tests  67 passed (67)`
- `All shared contract examples validated`
- `Local foundation verified: Node 22.23.3, npm 10.9.9`

A4. Set LB-00 to `DONE` in `harness/STATUS.md`, then:
```
git add CODEBUDDY.md AGENTS.md .codebuddy harness
git commit -m "LB-00: add CodeBuddy harness and confirm Lane A baseline"
```
Write the commit hash into the STATUS row (amend is not allowed; put it in the next task's commit if needed).

## Verify

- `npm run verify` → PASS (67 tests)
- `git log --oneline -1` → shows the LB-00 commit

## Acceptance

- [ ] Versions are exactly Node 22.23.3 / npm 10.9.9
- [ ] Baseline `npm run verify` passes with 67 tests
- [ ] Harness committed on `lane-b-codebuddy`

## Stop if

- Versions differ, `npm ci` fails, or the baseline verify fails (report the first error; Lane A must pass before Lane B changes anything).
