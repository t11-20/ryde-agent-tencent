# FairTrip — presentation outline (11 slides, one line each)

1. **Title:** Ryde — Multi-Agent Autonomous Dispute Resolution System · FairTrip · "Four agents resolve ride disputes transparently, with human oversight." · badges: SYNTHETIC DATA, DEMONSTRATION POLICY.
2. **Problem and users:** manual review of GPS, chat and payment records with 24–72 hour resolutions and inconsistent rulings (challenge-statement figures, not ours) hurts riders, drivers and support operations.
3. **Architecture diagram:** fixtures and demonstration policy → `@fairtrip/evidence` calculations → `DisputeSource` seam → Express API → three core agents plus the Risk Analyst → server-side money, with the observable UI and the evaluation runner on the side (SPEC §1 diagram).
4. **Agents and tools:** Rider Advocate and Driver Advocate request `get_evidence`/`get_policy` through a JSON tool protocol and cite only retrieved records; the Judge selects a remedy ID only — the server computes the amount.
5. **Live demo R1 (route deviation):** watch tool requests, retrieved chips and the Judge handoff on the transit-line timeline; ruling "Rider's claim upheld", server-computed refund S$1.98.
6. **Live demo N2 (no-show):** the driver's position is upheld on the evidence — remedy `keep_charge`, the charge stands, both parties still get explanations.
7. **Live demo N2H (escalation and human review):** high driver-side risk sends the completed ruling to the bench as a recommendation — "Sent to human review"; the Risk Analyst lane and panel show the cited signals, the ruling still says `keep_charge` (context only), and a human override to the no-show-fee refund is written back as a precedent that appears in a later run's "Precedents considered".
8. **Safety behaviour:** X1 (missing GPS) ends `incomplete` with no amount and a human-review note; X2 (prompt injection in chat) is treated as evidence only and ignored as an instruction.
9. **Measured results:** 27/27 runs (26 planned + 1 feedback probe) and 20/20 fixtures passed, exact money 27/27, citation validity 27/27, trace completeness 27/27, risk signals intact 27/27, 7 escalated runs (R1F ×3, N1R, N2H, X2, X6 — escalation changed no outcome), human-review feedback probe pass, consistency 3/3, p50 16.1 s, max 19.2 s (MiniMax-M3, 2026-10-13 scorecard, contract 0.3.0); token usage not measured.
10. **How we built it with CodeBuddy and one practical lesson:** task cards with golden-value tests kept every calculation honest; lesson — showing the exact object shape in prompts (counterevidence items) removed a whole class of schema-repair failures.
11. **Limitations and next steps:** synthetic data, demonstration policy, in-memory runs and precedent store, no reviewer authentication, local demo; next: persistence, reviewer identity, real policy text and hosted demo.
